CSS Anchor Positioning

Tether one element to another using only CSS. First give an element a name with anchor-name: --x. Then point an absolutely or fixed positioned element at it with position-anchor: --x.

Your browser doesn't support CSS Anchor Positioning yet.

1. position-area

The simplest option. Pick a cell of the 3×3 grid around the anchor, and the element goes there.

I'm anchored to the button

.tooltip-anchor { anchor-name: --tooltip-anchor; }

.tooltip {
  position: absolute;               /* required */
  position-anchor: --tooltip-anchor;
  position-area: top;               /* bottom, right, top right, … */
  margin-bottom: 0.5rem;            /* gap */
}

Watch out

  • The anchored element must be position: absolute or fixed. Otherwise every anchor property is ignored.

2. anchor() + anchor-size()

For precise control, use anchor(<edge>) in top / right / bottom / left, and anchor-size(<dimension>) in sizes.

.menu-button { anchor-name: --menu-button; }

.menu {                             /* popover: already position: fixed */
  position-anchor: --menu-button;
  inset: auto;                      /* undo the UA centering */
  margin: 0;
  top: anchor(bottom);              /* menu top = button bottom */
  left: anchor(left);               /* left edges line up */
  min-width: anchor-size(width);    /* at least as wide as the button */
}

Watch out

  • Popovers get inset: 0; margin: auto from the UA stylesheet, which centers them. Reset both, or your top / left fight with them.
  • popovertarget handles behavior (toggle, light dismiss, a11y). anchor-name / position-anchor handle layout.
  • position-anchor: auto uses the popover's implicit anchor (the invoking button). Leaving position-anchor unset does not (verified in Chrome 156).

3. position-try-fallbacks

Scroll down until the anchor reaches the top edge of the box. The tooltip runs out of room above and flips below the anchor.

Anchor
I flip when there's no room 
.scroll-area { position: relative; }   /* non-scrolling wrapper */

.flip-tip {                             /* sibling of the scroller */
  position: absolute;
  position-anchor: --flip-anchor;
  position-area: top;
  margin-bottom: 0.5rem;
  position-try-fallbacks: flip-block;   /* no room above? go below */
}

Watch out

  • If the tooltip sits inside the scroll container, overflow is checked against the whole scrollable content. The tooltip gets clipped and never flips. Put it outside the scroller as a sibling, inside a non-scrolling position: relative wrapper.
  • flip-block also mirrors margins (margin-bottom becomes margin-top). A plain position-try-fallbacks: bottom doesn't.
  • flip-inline does nothing for position-area: top, because a centered position mirrors to itself.
  • flip-block, flip-inline (comma) means two separate options. flip-block flip-inline (no comma) means one combined diagonal flip.

4. @position-try

When flip-* isn't enough, define your own fallback. Drag the bottom-right corner to make the box narrower. The tooltip moves below the anchor.

Anchor Tooltip 
.try-tip {
  position: absolute;
  position-anchor: --try-anchor;
  position-area: right;             /* preferred */
  margin-left: 0.5rem;
  position-try-fallbacks: --below;
}

@position-try --below {
  position-area: bottom;
  margin: 0.5rem 0 0;               /* reset margin-left too */
}

Watch out

  • resize needs overflow: auto, which makes the box a scroll container (same problem as Demo 3). Use a non-scrolling inner position: relative div as the containing block, and give it a height. Otherwise --below also overflows, and the browser falls back to the original position.
  • @position-try only replaces the properties it declares, so reset margin-left explicitly.

Tailwind

Tailwind 4.3.3 has no anchor utilities. Arbitrary values compile fine: [anchor-name:--x], [position-anchor:--x], top-[anchor(bottom)].
